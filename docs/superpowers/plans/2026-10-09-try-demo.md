# Try Demo (Frontend-Only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace code-join training sessions with a frontend-only Try Demo (Guest / FO / Admin) that runs on preloaded fixtures with zero backend contact, then fully remove the training sandbox.

**Architecture:** New `/demo` route tree under `src/demo/` with its own `DemoContext` (role, fixtures, scripted actions, simulated inbox). Demo screens reuse presentational components only (`ui/*`, rooms views, landing sections); containers are slim scripted re-implementations. An eslint `no-restricted-imports` rule makes backend contact in `src/demo/**` a lint error, so isolation is enforced, not promised. Cutover deletes the sandbox last, in one isolated commit per layer.

**Tech Stack:** React 19 + react-router-dom 7 (existing), sonner (existing toasts), vitest (existing suite), plain JS fixtures, no new dependencies.

**Spec:** User proposal 2026-10-09 (chat) as evaluated: hero keeps Browse Rooms primary + Try Demo secondary CTA; scripted golden paths only (3–5 journeys/role, rest view-only); full removal of the old system after demo ships; AI chatbot excluded from demo.

## Global Constraints

- No new npm dependencies for the demo.
- `src/demo/**` must never import `firebase/*`, `@/firebase/*`, or `@/services/*` — enforced by eslint (Task 4), not reviews.
- No changes to production behavior: every touch to existing files is additive until Phase 6 cutover.
- Chatbot (`ChatbotWidget`, `chatbotService`, worker AI routes, `AdminAssistantWidget`) is never mounted or imported in demo.
- CI must stay green after every task: `npm run lint`, `npm run knip`, `npm run test:run`, `npm run build`.
- Commit per task; push only when the user says so (standing rule).

## Review Focus

- Demo opened with no role selected shows the role picker, never a blank shell — pinned by the redirect pin in Task 8.
- Fixture dates are generated relative to `new Date()` — a tape chart with fixed 2026 dates goes empty; pinned by a recency assertion in Task 1.
- Every demo notification View link stays inside `/demo/*` — pinned by a link-prefix test in Task 5.
- A stale `bshm_training_override=true` in localStorage after cutover must not change prod behavior — pinned by a getCol passthrough test in Task 13.
- Cutover service edits must not alter prod queries — `getCol(base)` returns `baseName` unchanged; pinned by keeping the full existing suite green in Task 16.

import { describe, expect, it } from "vitest";
import { readFileSync, readdirSync, statSync } from "node:fs";
import { join } from "node:path";
function files(dir) {
  return readdirSync(dir).flatMap((e) => {
    const p = join(dir, e);
    return statSync(p).isDirectory() ? files(p) : [p];

- **Fixture drift.** Mitigation: shape test (Task 1) + parity doc (Task 8); any new service contract requires a fixture update in the same PR.

- **knip `files: error`.** Every `src/demo/**` file must be reachable from the App entry graph — no orphan helpers. knip runs in every phase verification.
