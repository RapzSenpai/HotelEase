1. Chatbot Mobile Touch Overlay Fix
Problem Statement
On mobile viewports, visitors visiting the Landing Page (/) could see action buttons like "Browse Rooms", "Sign In", and "View All Rooms", but tapping them produced no response.
Technical Root Cause
The ChatbotWidget component is rendered at the bottom of LandingPage.jsx. Inside ChatbotWidget.jsx:


1. The outer wrapper is fixed bottom-6 right-6 z-[100] flex flex-col items-end pointer-events-none.
2. The inner chat panel (380px × 540px) toggled opacity-100 (when open) vs opacity-0 pointer-events-none (when closed).
3. On mobile browsers (particularly Safari iOS and Chrome touch engines), an opacity-0 element rendered inside a fixed z-[100] container can still trap touch events or obscure underlying hit targets across a ~380px wide region.
Solution
Add the invisible (visibility: hidden) class whenever open === false. Setting visibility: hidden explicitly instructs the browser rendering engine to omit the element from touch/mouse hit-testing while retaining CSS transition compatibility when opening.

2. Guest Mobile Navigation Drawer
Problem Statement
When a guest logs in on a mobile device:


1. They are redirected to /my-bookings.
2. Navigation links ("Rooms", "My Bookings", "Favorites", "Profile") were styled with hidden sm:flex, hiding them completely on screen widths <640px.
3. The existing hamburger menu button was guarded by isFoOrAdmin, meaning guests had no hamburger menu and could only navigate using external links or the browser back button.
UX Decision & Rationale
* For Logged-In Guests (role === "guest"): Display a hamburger menu icon (<Menu> / <X>) on mobile header (sm:hidden). Tapping it reveals a sleek, backdrop-blurred drawer containing Rooms, My Bookings, Favorites, Profile, and Logout.
* For Unauthenticated Visitors (!user): Do NOT hide Login and Register inside a hamburger menu. Keep them directly visible on the mobile header for immediate accessibility and higher conversion.
